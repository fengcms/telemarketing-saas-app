## 二、接口依赖

### 2.1 POST /api/auth/change-password

- **已有实现**：`AuthService.changePassword(oldPassword, newPassword)`，调用方 catch `ApiException`
- **请求体**：`{ "oldPassword": "xxx", "newPassword": "xxx" }`
- **成功响应**：后端自增 tokenVersion，所有旧 token 失效 → **强制重新登录**
- **错误响应**：

| HTTP | code | 含义 | 前端处理 |
|:----:|------|------|---------|
| 400 | VALIDATION | 旧密码不正确 / 新密码不足 8 位等 | 对应输入框显示错误文字 |
| 401 | — | Token 过期 | 跳转登录页 |
| 500 | — | 服务器错误 | `AppToast` 提示 |

### 2.2 前端处理

- **成功**：清除本地 Token → AppToast "密码已修改，请重新登录" → 跳转登录页
- **失败**：显示后端返回的错误消息到对应输入框下方

## 三、密码强度规则

| 等级 | 条件 | 填充段 | 颜色 | 文字 |
|:----:|------|:------:|:----:|:----:|
| 弱 | 8-9 位，仅字母或仅数字 | 1 段 | `BrandColors.error` (#D54941) | "弱" |
| 中 | 8+ 位，字母+数字 | 2 段 | `BrandColors.warning` (#ED7B2F) | "中" |
| 强 | 8+ 位，字母+数字+特殊字符 | 3 段 | `BrandColors.primary` (#0052D9) | "强" |
| 非常强 | 12+ 位，大小写+数字+特殊字符 | 4 段 | `BrandColors.success` (#2BA471) | "非常强" |

强度实时计算（新密码每次输入变化时更新），输入为空时隐藏指示器。

## 四、表单校验顺序（提交时）

1. 旧密码为空 → "请输入旧密码"
2. 新密码为空 → "请输入新密码"
3. 新密码不足 8 位 → "密码至少 8 位"
4. 新密码与旧密码相同 → "新密码不能与旧密码相同"（前端前置校验）
5. 确认新密码为空 → "请再次输入新密码"
6. 确认新密码 ≠ 新密码 → "两次输入的密码不一致"

任一校验失败 → 对应输入框显示错误文字，停止提交。用户修改输入时清除该框的错误。

## 七、状态设计

| 状态 | 表现 |
|------|------|
| 初始 | 三个输入框空白，强度指示器隐藏，确认按钮可点击 |
| 输入中 | 聚焦框品牌蓝边框，新密码变更时实时计算强度 |
| 提交中 | 按钮显示 loading，输入框禁用 |
| 提交失败 | 按钮恢复，对应输入框下显示红色错误文字 |
| 提交成功 | 清 Token + AppToast + 跳转登录页 |
| 返回 | 有输入时弹出 `AppDialog.confirm` 确认"密码未修改，确定返回？" |
