# 日程列表页 UI 重组方案（SCHEDULE_LIST_REPLAN）

> 日期：2026-07-28
> 涉及页面：`lib/pages/schedules/schedule_list_page.dart`、`widgets/team_schedule_header.dart`、`widgets/app_scope_toggle.dart`
> 参考：线索列表页 `LeadsTopBar`（顶部蓝块 + 左侧胶囊 Tab 切换）
> 范围：**仅 UI 重组，业务逻辑零改动**（scope 切换 / 成员筛选 / 统计逻辑全部复用现有 notifier）

---

## 一、现状与痛点

### 痛点 1：视角切换（我的 / 团队）放置与形态都不对

- **当前实现**：`schedule_list_page.dart` 把视角切换放在 `AppBar` 的 `actions` 右侧，用 `AppScopeToggle`。
- **`AppScopeToggle` 的本质**：它只渲染「当前选中项的 label」（"我的"或"团队"），点一下**循环切到下一个**——是个单状态文字药丸，**不展示两个可选项**。
- **对照线索列表页**：`LeadsTopBar` 在**蓝色顶栏左侧**并排两个白色胶囊 Tab（"我的线索 | 公海线索"），选中白底蓝字、未选中透明白底白字，一眼可见、一点即切。
- **问题**：日程页把"作用域切换"塞进 AppBar 角落，且组件形态错误（单状态 vs 双选项），所以你感觉"显示我的 / 显示团队不合理"——它根本没表达"可切换"的语义。

### 痛点 2：标题栏下方"今日待办 / 逾期 / 员工筛选"组织混乱

- **当前实现**：仅 `scope == 'team'` 时，body 顶部渲染 `TeamScheduleHeader`：
  - `_SummaryBar`：`今日待办 N 条 · 逾期 M 条`（灰底一行，48 高）
  - `_OwnerFilterButton`：`员工：全部成员 / ●姓名`（灰底一行，44 高，点开成员抽屉）
- **问题**：
  1. 两行灰底、无卡片感，和下方列表区灰底连成一片，边界不清
  2. 与状态 Tab 栏（"待办 X / 已完成 Y"带计数）信息层级重复——都在数"待办"
  3. **仅 team 视角显示**，我的视角直接进 Tab+列表 → 两视角顶部结构不对称
  4. 统计条和员工筛选割裂成两行，关系不清晰

---

## 二、目标

- 视角切换**对齐线索页**：顶部蓝块左侧并排白色胶囊 Tab（我的 / 团队），可见、可点
- 把"今日待办 / 逾期 / 员工筛选"重组成**规整概览卡**（白底圆角 10 + 微阴影，对齐 `StatCard` / 线索卡），两视角对称
- 信息层级清晰：**视角（谁的）→ 概览（关键指标）→ 状态（哪种）→ 列表**
- 纯 UI，业务逻辑零改动

---

## 三、详细方案

### 3.1 视角切换（对齐线索页 `LeadsTopBar` 胶囊 Tab）

- **方案 A（推荐）**：日程页 `AppBar` 改为**自定义蓝色顶栏**（仿 `LeadsTopBar`）——左侧"我的 | 团队"白色胶囊 Tab（仅 TM/TA 显示），右侧放搜索图标。标题"日程"融入（同线索页无单独大标题，胶囊 Tab 即充当主标题）。
- **方案 B（轻改）**：保留 Flutter `AppBar`（标题"日程"），把视角切换做成 `title` 区一行"我的 | 团队"胶囊（在标题旁/下）。
- **胶囊样式**：复用 `LeadsTopBar._buildTabItem`（白底蓝字 / 透明白底白字，圆角 6）。建议**抽公共组件 `AppScopeSegmented`**（白底胶囊切换、蓝底适配），供线索页 `LeadsTopBar` 与日程页复用，从根上防再漂移。

### 3.2 概览区重组（白底卡，圆角 10 + 微阴影）

新增 `ScheduleOverviewCard`（或复用 `StatCard` 风格）：

```
┌─────────────────────────────────────────┐
│  今日待办  N       逾期  M               │   ← 两格，今日=蓝、逾期=红
│  ─────────────────────────────────────  │
│  👤 ●姓名/全部成员        ▾              │   ← 仅团队：员工筛选入口
└─────────────────────────────────────────┘
```

- 行 1：`今日待办 N`（primary 蓝）· `逾期 M`（error 红）两格
- 行 2（**仅 team**）：`员工筛选`（person 图标 + 颜色圆点 + 名称/全部成员 + 下拉箭头），点开现有成员抽屉
- 两视角对称：**我的视角也显示行 1**（今日待办/逾期，本地统计），团队多行 2
- 数字颜色语义沿用现有约定：今日=蓝、逾期=红

### 3.3 与状态 Tab 栏（待办 / 已完成）的关系

- 概览卡看 **"今日窗口 / 逾期"紧急度**（时间维度，管理最关心今天该跟什么、谁逾期）
- 状态 Tab 看 **"待办 / 已完成"总量**（状态维度）
- 维度不同，保留两层不冲突；为避免混淆，概览卡只放时间敏感指标，不重复"全部待办"总量

## 五、实施计划

1. （若选 A/B 抽组件）新增 `lib/widgets/app_scope_segmented.dart` 公共胶囊切换组件
2. 日程页 `AppBar` 改蓝块顶栏（或 title 胶囊行），接入 `scope` 切换（复用 `switchScope`）

5. 我的视角概览卡本地算今日待办/逾期（复用已有 `_countTodayPending` / `_countOverdue`）
6. `flutter analyze` 校验 + 真机热重启验证
7. 写 `PROGRESS_SCHEDULE_LIST_UI` 进度文档 + `commit & push`

## 六、影响范围与风险

- **仅 UI 重组**；`scope` 切换 / 成员筛选 / 统计逻辑全部复用现有 `scheduleListProvider` notifier，不碰业务
- 我的视角新增概览卡需本地统计，已有 `_countTodayPending` / `_countOverdue` 可直接复用

- 纯 UI 零业务改动，`flutter analyze` 0 error 为目标
