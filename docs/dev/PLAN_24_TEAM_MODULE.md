# 开发规划：团队模块（v0.23~v0.25）

> 覆盖设计文档 20（已归档）-23，团队三个功能散落在现有 Tab 中。
> 可见角色：TM（租户经理）、TA（租户管理员）；TE 不可见。

---

## 一、架构总览

团队模块不是 3 个独立的新页面，而是对 **3 个现有 Tab 页面的角色感知增强**：

| 团队功能 | 所在 Tab | 形式 | 工作性质 |
|---------|---------|------|---------|
| 团队线索池 | 「线索」Tab (Tab 2) | TM/TA 登录后自动 `scope=all`，现有列表增加归属人显示 + 统计摘要条 + 归属人筛选按钮 | **改动最小** |
| 团队日程 | 「日程」Tab (Tab 3) | 日程列表顶部增加「我的/团队」切换控件，切到团队后加载全团队日程 + 归属人标签 + 员工筛选 + 统计摘要 | **中等改动** |
| 团队统计 | 「我的」Tab (Tab 4) → 入口 | **独立 Push 页面**，包含概览卡片/转化漏斗/饼图/折线图/坐席排行，需引入 fl_chart | **改动最大** |

### 入口架构

```
线索 Tab ── TM/TA 进入自动 scope=all → 现有列表（已实现 scope 切换）→ 增加归属人显示
日程 Tab ── 新增「我的/团队」切换 → 团队视图
我的 Tab ── 团队统计入口（仅 TM/TA 可见）→ Push 到团队统计页
```

三个功能**可独立开发、独立测试、独立发布**，无前后依赖。

## 二、分阶段规划

### 阶段一：团队线索池（建议 v0.23，最小改动）

> 对应设计文档 23
> 工作量：约 100-150 行改动（全在现有代码基础上）

**核心改动：**

1. `LeadCard` 增加显示 `ownerName`（仅在 `showOwner=true` 且 `ownerName` 非空时显示）
2. 线索列表页顶部增加**统计摘要条**（`AppBar` 下方、搜索栏上方）：
   - 仅显示"共 X 条"（来自 `data.total`）
   - `BrandColors.bgGray` 灰底，40px 高
3. **归属人筛选按钮**（筛选栏中新增）：
   - 点击弹出 BottomSheet，选项来自 `GET /api/tenant/options/users`
   - 选中后调接口 `&ownerId=xxx` 筛选
4. 提取**归属人颜色映射工具方法**（`lib/theme/user_color.dart`）：
   - 8 色预设池，userId.hashCode 取模
   - 后续团队日程复用

**前置条件：**
- 现有线索列表已支持 `scope=all`（`LeadsListPage` 的 scope 切换）
- `LeadsFilterSheet` 已存在状态/分类/项目筛选
- `LeadCard` 已有 `showOwner` 参数

**预判疑问：**
- Q：TM/TA 不允许领取公海，但现有的 `LeadsTopBar` 里有公海 Tab——需要**仅在 TE 角色显示公海 Tab**（当前实现已经是这样）
- Q：`scope` 切换逻辑——当前 `leadListProvider` 用 `ScopeNotifier` 管理 scope，TM/TA 进页面时发 `scope=all`，需要确保初始化时按角色自动设对

### 阶段二：团队日程（建议 v0.24，中等改动）

> 对应设计文档 22
> 工作量：约 200-300 行改动 + 新建 `lib/pages/schedules/team_schedule_view.dart`

**核心改动：**

1. **日程列表页增加「我的/团队」切换**（`TDSegmentedControl`，仅 TM/TA 可见）：
   - 默认选中"我的"
   - 切换不重新创建页面，只改数据源
   - 我的视图 = 现有个人日程（不变）
   - 团队视图 = 全团队日程（`GET /api/tenant/schedules?status__in=...` 自动返回全团队）
   
2. **团队视图特有组件**（放在 `schedules/` 目录下）：
   - 统计摘要条（今日待办 N 条 · 逾期 M 条）
   - 员工筛选下拉（`GET /api/tenant/options/users`）
   - 日期筛选（今天/明天/本周/自定义）
   - 归属人颜色圆点 + 姓名标签（复用 `user_color.dart`）
   - 逾期标记
   
3. **团队日程卡片**：
   - 复用现有日程卡片布局 + 增加归属人行
   - 点击跳转日程详情（传递 scheduleId）

**前置条件：**
- 现有 `ScheduleListPage` 需重构为可支持双视图（我的/团队）
- 需要暴露 `ScheduleService.fetchSchedules` 的 `userId` 参数（目前前端过滤）

**关键决策：**
- 团队日程数据一次性加载 vs 分页加载：设计文档建议一次性加载（10-50人×每人3-5条 = 30-250条，可控）
- 员工筛选为**前端过滤**（数据已全部加载）

---

### 阶段三：团队统计（建议 v0.25，最大改动）

> 对应设计文档 21
> 工作量：约 400-500 行新代码 + 引入 `fl_chart` 依赖

**核心改动：**

1. **新建独立页面** `lib/pages/stats/team_stats_page.dart`：
   - AppBar "团队看板" + 右侧刷新按钮
   - 可滚动长页面 + 吸顶日期选择器

2. **接口集成**：
   - 新建 `StatsService`（`GET /api/tenant/stats?dateFrom=...&dateTo=...`）
   - 响应映射：total / byStatus / funnel / agentPerf / dailyTrend / poolTotal 等

3. **UI 组件**（从简到繁）：
   - 日期范围选择器（TagGroup：今日/本周/本月/自定义 + 原生 `showDateRangePicker`）
   - 4 张概览卡片（2×2 网格，48sp 大数字 + 千分位 + 大数字降级）
   - 转化漏斗（4 级横向进度条，CustomPaint 自绘，不用 fl_chart）
   - 状态分布（环形饼图，fl_chart `PieChart`）
   - 逐日趋势（3 线折线图，fl_chart `LineChart`）
   - 坐席绩效排行（可排序列表，按转化率/转化数/跟进数/接通数）

4. **入口接入**：
   - `ProfilePage` 中「团队统计」入口（TM/TA 可见、TE 隐藏）

**关键决策：**
- 转化漏斗用 `CustomPaint` 自绘（简单、无额外依赖）
- 饼图和折线图用 `fl_chart`（已广泛使用、纯 Flutter）
- 简化动画（设计文档要求复杂入场动画，MVP 先不做）

## 五、建议开发顺序

推荐按照 **改动量从小到大** 的顺序推进：

1. **① 团队线索池** → 改动最小，快速见效，验证 TM/TA 角色感知模式
2. **② 团队日程** → 中等改动，日程页面已有良好基础
3. **③ 团队统计** → 最大改动（图表），最后攻坚

每个阶段独立测试、独立提交，你可以在任意阶段后插队其他需求。
