# 2026-07-26 工作日志

## 修复：web 上「登录正常、进首页不发包」崩溃

### 现象
`flutter run -d chrome --dart-define=DEV_TOOLS=true` 登录后首页不发包；安卓真机正常。
最初误判为 CORS（Authorization 头预检），用户贴出 Console 红报错后推翻。

### 根因（Riverpod 构建期改 provider）
- `lib/providers/schedule_stats_provider.dart` 的 `ScheduleStatsNotifier.load()`
  第一行是**同步** `state = state.copyWith(isLoading: true)`。
  notifier 构造器里调用了 `load()`，且 `profile_page.dart` 的 `initState` 也同步调了 `.notifier.load()`。
- `MainShell` 用 `IndexedStack` 一次性挂载 4 个 Tab，进首页时 `ProfilePage.initState`
  触发该同步 setState → Riverpod `_debugCanModifyProviders` 抛错 → **整个 MainShell 构建崩溃**，
  `HomePageNotifier.loadData()` 没机会跑 → 表现为「首页不发包」。
- 仅 web 暴露：debug 构建期保护在原生端时序差异下未触发。

### 修复
1. `schedule_stats_provider.dart`：删除 `load()` 首行同步 setState，初始 loading 态改到
   构造器 `super(const ScheduleStatsState(isLoading: true))`。此后 `load()` 只在 `await` 后 setState，合法。
2. `profile_page.dart`：删掉 `initState` 里多余的 `ref.read(scheduleStatsProvider.notifier).load()`
   （notifier 构造已自动 load，避免重复请求）。
- `flutter analyze` 通过，无报错。

### 排查要点（经验）
- Riverpod 仅拦截 **build/initState/didChangeDependencies 等构建期**的 provider 修改；
  事件回调（onRefresh/按钮）里调 `.notifier.refresh()` 安全。
- 全仓扫描：其余 `notifier.refresh()` 均在事件回调中，无同类隐患。
- 首页 `_safeCall` 吞异常导致此类问题静默，建议开发期加 `debugPrint`。

## 二次排查：崩溃修好后仍「进首页不发包」
- 现象：红报错消失，但登录后首页不发请求；控制台重复 `Selected call is null`（来自 alice-1.0.0
  `alice_memory_storage.dart` 的 `addError/addResponse` 找不到对应 call）。
- 结论方向：Alice 拦截器确实收到请求（`onRequest` 已 addCall），但请求最终以错误结束且
  `error.requestOptions.hashCode` 匹配不到原 call → 请求被浏览器层拦（疑似 CORS 对 `Authorization`
  头预检失败，登录为 public 接口不带 auth 头故正常）。
- 根因尚未 100% 坐实（用户在 web 上「确认 CORS 没问题」可能只验了登录/public 接口）。
- 措施：`lib/services/api_client.dart` 的 token 拦截器加 `enableDevTools` 守卫的 `[API][REQ]/[RESP]/[ERR]`
  debugPrint（正式包编译期消除），让用户重跑 web 抓真实错误（type/msg/status/auth 头）。
- 待用户回贴控制台 `[API]` 行确认根因（CORS vs 401 vs 网络）。
