## 设置页新增「清除缓存」功能（v0.38，已开发+装真机，待实测）
- 需求：设置页新增「清除缓存」菜单，清除本机所有接口缓存（含登录凭据）后跳登录页重新登录。
- 决策（AskUserQuestion 确认）：① 纯本地清除，不调后端 /api/auth/logout，不吊销会话、不影响其他设备；② 保留账号预填（LocalStorageService 的 saved_login_email/password 不清）。
- 实现：`cache_coordinator.dart` 加 `clearAllData()`（清用户私有 + options.clearAll + tenantService.clearAll + homePage.notifier.reset + teamStats invalidate）；`auth_provider.dart` 加 `clearLocalCache()`（tokenStorage.clearAll + clearAllData + 置 unauthenticated 跳登录）；`settings_page.dart` 账户操作区加「清除缓存」ListTile + `_onClearCache`（二次确认 + popUntil first）。
- 坑：`homePageProvider` 是 StateNotifierProvider，`.read()` 返回 state 而非 notifier，reset() 在 notifier 上需用 `homePageProvider.notifier`；`tenantServiceProvider` 定义在 auth_provider 而非 services 层，cache_coordinator import auth_provider 形成 provider 循环依赖（Riverpod 下安全，仅方法体内使用）。

## 冷启动线索卡片分类/项目显示成 ID（已修复，待实测）
- 现象：后台杀掉 App 重开 → 进线索列表 → 分类/项目标签显示原始 ID，稳定复现；用户确认磁盘有缓存数据。
- 根因：`OptionsCacheService` 磁盘 key 带租户前缀 `cache_options_${_tid}_categories`，`_tid` 取 `tenantServiceProvider.cachedTenantId`。冷启动线索卡片 `lead_card` 的 `FutureBuilder` 立即调 `cache.getCategoryName()` → `_ensureLoaded()` → `_loadFromLocal()` 读磁盘时，`TenantService._loadFromLocal()`（异步）尚未跑完，`cachedTenantId` 为 null → `_tid=''` → 用空前缀 key 读到空数据；而 TTL 内（10h）不回退 API 刷新 → `getCategoryName` 找不到映射，返回原始 id。与租户服务 `fetchProfile()` 异步竞速导致。
- 修复：`options_cache_service.dart` 的 `_ensureLoaded()` 在首次 `_loadFromLocal()` 前先 `await tenantServiceProvider.fetchTenantId()`（内部先 `_loadFromLocal` 从磁盘取 id，不依赖网络；仅租户缓存过期才请求 profile），加 `_tenantIdEnsured` 标志避免重复；`clearAll()` 重置该标志。

## 清除缓存后重新登录列表卡骨架屏（修复，待实测）
- 现象：设置页「清除缓存」→ 跳登录页 → 不杀 App 直接重新登录 → 线索列表一直骨架屏、下拉刷新也不行；杀 App 重开重新登录正常。稳定复现。
- 根因（死锁）：`api_client.dart` 的 401 自动刷新拦截器 `_refreshAndRetry` 在并发 401 时，第一个请求刷新（`_isRefreshing=true`），其余塞进 `_refreshQueue` 挂起；而刷新流程 `refreshToken == null` 提前 `return null` 时 `finally` 只复位 `_isRefreshing`、**没清空 `_refreshQueue`**，队列请求 `completer.future` 永不 resolve → `options.getCategories` 挂起 → `lead_list_provider._loadOptions` 的 `Future.wait` 永不返回 → `_loadInitial` 的 `Future.wait([_fetchPage,_loadOptions])` 永不返回 → `isInitialLoading` 永远 true → 骨架屏。
- 跨存活：`apiClient` 是单例 Provider，清除缓存未重建，其 `_isRefreshing`/`_refreshQueue`/`optionsCacheService._loadingFuture` 实例级脏状态跨「清除缓存→重新登录」存活 → 重新登录后列表仍卡。
- 双保险修复：① 治本——`_refreshAndRetry` 的 `finally` 兜底 `for (pending in _refreshQueue) pending.completer.complete(null); _refreshQueue.clear();`；② 对齐杀 App 正常——`clearLocalCache` 末尾 `_ref.invalidate(apiClientProvider)`，重建 apiClient 及派生 service（tenant/options/lead...），清所有脏状态。
- 文档：`PLAN_FIX_CLEAR_CACHE_DEADLOCK-2026-07-28.md`；`flutter analyze` 2 文件 No issues；build + 装真机待完成。
